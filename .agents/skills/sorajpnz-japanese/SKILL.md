# SoraJPNZ Japanese

SoraJPNZの日本語を、Sora本人の生活から出た言葉として読める状態にする。文章を一律に整えることより、具体性、正直さ、読みやすさを優先する。

## 最初に読むもの

1. リポジトリ直下の `AGENTS.md`
2. `docs/content/SORAJPNZ_JAPANESE_STYLE.md`
3. 記事なら `docs/content/SORAJPNZ_EDITORIAL_WORKFLOW.md`
4. UI変更を伴う場合は `DESIGN.md`
5. ツール変更なら該当する `docs/products/` の仕様書

## 優先順位

判断がぶつかった場合は、次の順で守る。

1. 確認済みの事実、出典、法務・安全・プライバシー上の境界
2. ユーザーが提供した体験、言葉、公開範囲
3. SoraJPNZの日本語スタイル
4. `natural-japanese`など汎用チェックの提案

汎用ルールに合わせるために、数字、注意書き、固有名詞、本人らしい言い回しを消してはいけない。

## 作業手順

### 1. 読者と一文目を決める

- 誰が、何に迷って、このページを開くのかを一文で置く。
- ページを読んだあとに取れる行動を一つ決める。
- Aucklandでの具体的な場面があるなら、抽象的なブランド説明より先に使う。

### 2. 変えてはいけない情報を分ける

- 数字、日付、出典、ルート、公開状態、免責、計算条件を先に確認する。
- 体験と一般情報を混ぜない。
- 法律、移民、税務、雇用、投資、釣りのルールは、現在の一次情報と確認日がない限り断定しない。

### 3. Soraの声で書く

- 本文の一人称は原則として「私」。カード見出しの「Soraメモ」などは使ってよい。
- 「Aucklandで暮らしていて感じるのは」のように、経験の立ち位置を短く示す。
- です・ます調を基本にする。親しみは出しても、馴れ馴れしくしない。
- 一段落に一つの役割を持たせる。長い説明は二文に分ける。
- 同じ長さ、同じ書き出し、同じ結論のカードを三つ以上並べない。

### 4. 汎用チェックをかける

- `natural-japanese`が利用できる場合はquick相当で確認する。
- 実行環境がなければ、同skillの手動チェックリストを使う。
- 「〜していきます」「整理します」「判断材料」「〜のための場所です」の反復を確認する。
- 「〜ではなく、〜」は、本当に読者の誤解を正す一箇所だけに絞る。
- 指摘は機械的に全修正せず、文脈に必要な表現は理由を持って残す。

### 5. 公開面を確認する

- CTAが何を開くか、押した後の結果が文面どおりか確認する。
- 日本語と英語のルートを切り替え、存在しない翻訳先へ送らない。
- 記事のindex/noindex、canonical、sitemap、Blog Hub掲載状態を依頼どおり保つ。
- TypeScript check、本番build、モバイル表示を確認する。

## やらないこと

- 英語原文の語順を残した直訳
- ブランド説明だけで埋めた導入
- 根拠のない成功談、煽り、断定
- すべての見出しや段落を同じ型へそろえること
- 本人の体験がない箇所を、もっともらしいエピソードで補うこと
- 注意書きを弱めるだけの「自然な日本語化」
- ユーザーの承認なしに、個人の家計、勤務先、住所、位置情報を具体化すること

## 仕上がりの基準

見出しと各段落の一文目だけを読んでも内容が追える。さらに全文を声に出すつもりで読み、Sora本人が友人へ説明しても不自然でないことを確かめる。
