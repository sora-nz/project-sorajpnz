# SoraJPNZ 日本語スタイルガイド

## このガイドの役割

SoraJPNZの日本語を「正しいけれど誰が書いたか分からない文章」にしないための基準です。読みやすさの一般ルールは `natural-japanese`で確認し、この文書ではSoraJPNZらしさと安全上の境界を扱います。

文章の中心に置くのは、Aucklandで実際に暮らしながら迷ったことです。数字や一次情報は、その経験を大げさにせず確かめるために使います。

## 読者

主な読者は、すでにNZで暮らしている日本語話者と、渡航や長期滞在を具体的に考えている人です。生活費、仕事、お金、今後の暮らしに不安があり、成功談よりも条件や違いを知りたい人を想定します。

すべての読者がNZの制度や英語表現に詳しいとは限りません。現地で一般的な言葉でも、初めて出すときは文脈から意味が分かるようにします。

## 声の中心

SoraJPNZの文章は、次の四つを同時に満たします。

- **個人的**: 「私がAucklandで暮らしていて感じたこと」を隠さない。
- **具体的**: 家賃、車、勤務時間、海へ行く移動など、実際の場面から書く。
- **慎重**: 一人の経験を、NZ全体の正解として言い切らない。
- **実用的**: 読者が自分の条件へ置き換えられる数字、問い、ツールを渡す。

基本はです・ます調です。講師のように教えるより、少し先に試した人が「私はここで迷いました」と共有する距離感を保ちます。

## 一人称と主語

本文の一人称は原則として「私」を使います。「Sora」は `Soraメモ` やプロフィールなど、名前がラベルとして働く場所に限ります。

経験を書くときは、誰の経験かを短く示します。

- 自然: `私がAucklandで暮らしていて気になったのは、家賃より先に毎週お金が出ていく感覚でした。`
- 避ける: `Aucklandでは誰もが家賃に苦しみます。`

後者のように一般化するには、対象期間と出典が必要です。

## 文と段落

- 最初の一文で、その段落が何を伝えるか分かるようにする。
- 一文に条件や列挙を詰め込みすぎない。長くなったら二文に分ける。
- 短い文と長い文を混ぜる。すべてを同じ長さにそろえない。
- 一段落は一つの役割に絞る。
- 箇条書きは、本当に横並びの項目を短く見せたいときだけ使う。
- UIカードを三つ並べる場合も、説明文を同じ文型へ無理にそろえない。

## 見出し

見出しは、読者が拾い読みできる言葉にします。すべてを結論文にする必要はありません。ラベル型と話し言葉に近い見出しを混ぜ、同じ型を続けないようにします。

- 良い例: `時給だけでは、月の余白は分からない`
- 良い例: `車を持つということ`
- 良い例: `参考にした公式情報`
- 避ける例: `包括的な生活費分析`
- 避ける例: `データが示すNZ生活の真実`

## SoraJPNZで使う言葉

- `NZ`: 見出し、CTA、短いUIで使ってよい。
- `ニュージーランド`: 初出、SEO説明、制度や公式情報の文脈で使う。
- `Auckland`: 現在のサイト表記として維持する。文章内で無理に「オークランド」へ統一しない。
- `SoraJPNZ Notes`: サービス名として維持する。一般名詞なら「ノート」「記事」を使う。
- `Tools` / `Projects`: ナビゲーションや固有のコンテンツ群では維持してよい。本文では「計算機」「プロジェクト」と書く。
- `spearfishing`: 日本語本文では原則「スピアフィッシング」。必要なら初出で短く説明する。
- `Living Wage`、`KiwiSaver`、`student loan`など: 機能や意味が文脈から分からない場合は一言添える。

英単語を並べるときは、サイト内の固有名か、NZで実際に使われる言葉かを確認します。日本語で十分伝わる箇所まで英語にしません。

## 画面ごとの書き方

### Home

一つのノートや一つの計算機だけをサイト全体の目的にしません。SoraJPNZが、生活の疑問をNotes、Tools、Projectsへつなぐ個人サイトだと伝えます。抽象的なブランド宣言より、家賃、車、仕事など具体的な入口を優先します。

### Blog / Notes

導入は「この記事では解説します」だけで始めず、Soraが実際に迷った場面や読者の疑問から入ります。体験、数字、一次情報を同じ確信度で書きません。詳細な出典は本文の流れを止めない場所へまとめても構いません。

### Calculator / Tools

入力すると何が分かるかを先に書きます。「意思決定支援」「脆弱性」などの概念語は、必要な場面以外では日常語へ置き換えます。判定は答えではなく、入力した前提を比べる目安だと示します。

### Projects

技術名の羅列より先に、どんな疑問を、何を使って、どの形まで作ったかを書きます。採用担当者が読む可能性もあるため、データソース、前提、制約、検証を隠しません。

### CTA

押した先でできることを、そのまま動詞で書きます。

- `月の残りを試算する`
- `ノートを読む`
- `プロジェクトを見る`

`今すぐ人生を変える`のような煽りや、結果を約束する表現は使いません。

## 反復に注意する表現

次の言葉は禁止ではありません。ただし、同じページで繰り返すと説明文らしさやAIらしさが強くなるため、必要な一箇所に絞ります。

- `整理します / 整理しています`
- `判断材料`
- `〜のための場所です`
- `数字と実体験を行き来する`
- `答えを決めつけず`
- `現実的に考える`
- `〜していきます`
- `重要なのは`
- `〜ではなく、〜です`

言い換えること自体を目的にしません。Aucklandで何が起きたのか、読者が何を入力・比較・確認できるのかへ戻ると、自然に具体化できます。

## 事実、体験、意見

### 体験

`私の場合`、`Aucklandで暮らしていて`など、話者が分かる形で書きます。個人の経験から全員への結論へ飛ばしません。

### 数字と制度

最低賃金、Living Wage、税、家賃、為替、ビザ、釣りのルールなど、変わり得る情報には出典名と対象日・期間を付けます。公開前には確認日も残します。

### 助言との境界

SoraJPNZは、移民、税務、雇用、法律、金融、投資の助言をしません。注意書きを自然にするために意味を弱めてはいけません。読者が重要な判断をする箇所では、公式情報や資格を持つ専門家の確認先を示します。

## 推敲の順番

1. 読者の疑問と、このページで渡す一つの価値を確認する。
2. 数字、日付、出典、免責、公開設定を固定する。
3. 一般論だけの段落を探し、本人の体験か具体的な機能へ置き換える。
4. 同じ書き出し、同じ文末、同じカード構成が三回続いていないか見る。
5. `natural-japanese`のquickチェック、または手動チェックを行う。
6. 見出しと各段落の最初の一文だけを読む。
7. 最後に、Soraが友人へ声に出して説明しても不自然でないか確認する。

## 現在の限界

このガイドは、既存サイトの文章とユーザーが明示した好みから作った初版です。今後、Sora本人が書いたYouTube台本、SNS投稿、記事など3〜5本を選び、語彙、文末、話の運び方を追加で確認すると、さらに本人らしい文体へ更新できます。
